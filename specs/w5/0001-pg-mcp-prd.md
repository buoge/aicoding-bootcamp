# Postgres MCP Server 产品需求文档 (PRD)

## 1. 项目概述

### 1.1 项目背景
构建一个基于 Model Context Protocol (MCP) 的 PostgreSQL 智能查询服务器，允许用户通过自然语言描述查询需求，自动生成并执行 SQL 查询，返回查询结果。

### 1.2 项目目标
- 提供自然语言到 SQL 的转换能力
- 支持多数据库连接和 schema 自动发现
- 确保查询安全性（只允许 SELECT 查询）
- 提供查询结果验证和优化
- 集成 Kimi-K2 大语言模型进行智能 SQL 生成

## 2. 功能需求

### 2.1 数据库连接管理

#### 2.1.1 数据库配置加载
- **需求编号**: FR-001
- **需求描述**: MCP 服务器启动时从配置文件读取数据库连接信息
- **详细说明**:
  - 支持多个 PostgreSQL 数据库连接
  - 配置格式：JSON/YAML
  - 包含字段：host, port, database, user, password, sslmode 等
  - 支持环境变量覆盖配置
- **优先级**: P0
- **验收标准**:
  - 服务器启动时成功加载所有配置的数据库连接
  - 错误的数据库配置不会导致服务器崩溃
  - 提供清晰的错误日志

#### 2.1.2 Schema 自动发现与缓存
- **需求编号**: FR-002
- **需求描述**: 自动获取并缓存所有可访问数据库的 schema 信息
- **详细说明**:
  - 获取每个数据库的：
    - 表（tables）列表及结构
    - 视图（views）列表及结构
    - 自定义类型（types）
    - 索引（indexes）
    - 主键和外键约束
  - 将 schema 信息缓存到内存中
  - 提供手动刷新 schema 缓存的接口
  - 定期自动刷新（可配置间隔）
- **优先级**: P0
- **验收标准**:
  - 启动后 30 秒内完成所有数据库的 schema 发现
  - Schema 信息准确完整
  - 缓存更新不会影响正在处理的查询请求

### 2.2 自然语言查询处理

#### 2.2.1 查询请求接收
- **需求编号**: FR-003
- **需求描述**: 接收用户的自然语言查询请求
- **详细说明**:
  - 通过 MCP 协议接收查询请求
  - 请求格式：包含用户输入的自然语言、目标数据库标识
  - 支持上下文对话（多轮查询）
  - 请求超时控制（默认 30 秒）
- **优先级**: P0
- **验收标准**:
  - 正确解析 MCP 协议请求
  - 验证请求格式和必需字段
  - 提供友好的错误提示

#### 2.2.2 Kimi-K2 模型集成
- **需求编号**: FR-004
- **需求描述**: 集成 Kimi-K2 大模型进行 SQL 生成
- **详细说明**:
  - 构建优化的 prompt，包含：
    - 用户的自然语言查询
    - 目标数据库的 schema 信息
    - 查询历史和上下文（如适用）
    - 示例查询（few-shot learning）
  - 调用 Kimi-K2 API (kimi-k2-thinking-turbo)
  - 配置参数：temperature=0.1（保证 SQL 准确性）
  - 实现重试机制和错误处理
  - API 调用超时控制（默认 60 秒）
- **优先级**: P0
- **验收标准**:
  - SQL 生成成功率 > 95%
  - 平均响应时间 < 5 秒
  - 生成的 SQL 语法正确率 > 98%

### 2.3 SQL 查询处理与执行

#### 2.3.1 SQL 安全性校验
- **需求编号**: FR-005
- **需求描述**: 对生成的 SQL 进行安全性校验
- **详细说明**:
  - 只允许 SELECT 查询语句
  - 禁止的 SQL 类型：
    - DDL（CREATE, ALTER, DROP, TRUNCATE）
    - DML（INSERT, UPDATE, DELETE）
    - TCL（BEGIN, COMMIT, ROLLBACK）
    - 其他危险操作（DROP DATABASE, etc.）
  - 使用 SQL 解析器进行语法分析
  - 黑名单关键词检查
  - 提供详细的错误信息
- **优先级**: P0
- **验收标准**:
  - 100% 拦截非 SELECT 语句
  - 零误报（合法的 SELECT 查询不会被拦截）
  - 校验时间 < 100ms

#### 2.3.2 SQL 执行与测试
- **需求编号**: FR-006
- **需求描述**: 在安全环境中测试 SQL 查询
- **详细说明**:
  - 创建只读事务执行查询
  - 设置查询超时（默认 30 秒）
  - 限制返回行数（默认 1000 行，可配置）
  - 捕获并处理数据库错误
  - 记录查询执行时间和资源消耗
  - 支持 EXPLAIN ANALYZE 获取查询计划
- **优先级**: P0
- **验收标准**:
  - 查询成功率 > 98%
  - 错误信息清晰易懂
  - 不会对生产数据库造成性能影响

### 2.4 结果验证与优化

#### 2.4.1 查询结果验证
- **需求编号**: FR-007
- **需求描述**: 使用 Kimi-K2 验证查询结果的相关性和完整性
- **详细说明**:
  - 将用户的原始查询、生成的 SQL、查询结果摘要发送给 Kimi-K2
  - 验证维度：
    - 结果是否符合用户意图
    - 数据完整性检查
    - 是否存在明显的数据异常
  - 返回验证分数（0-100）和建议
  - 如果验证失败，提供优化建议
- **优先级**: P1
- **验收标准**:
  - 验证准确率 > 90%
  - 对异常结果的识别率 > 85%
  - 不影响主流程响应时间

#### 2.4.2 SQL 优化建议
- **需求编号**: FR-008
- **需求描述**: 为慢查询提供优化建议
- **详细说明**:
  - 分析查询执行计划
  - 识别潜在的性能问题：
    - 全表扫描
    - 缺少索引
    - 复杂的嵌套查询
    - 大数据量排序
  - 提供具体的优化建议
  - 生成优化后的 SQL 示例
- **优先级**: P2
- **验收标准**:
  - 准确识别性能瓶颈
  - 建议具有可操作性
  - 优化后的查询性能提升 > 50%

### 2.5 响应生成

#### 2.5.1 结果格式化
- **需求编号**: FR-009
- **需求描述**: 格式化查询结果并生成响应
- **详细说明**:
  - 返回数据结构：
    - 生成的 SQL 语句
    - 查询结果（JSON 格式）
    - 结果摘要（统计信息）
    - 执行元数据（执行时间、扫描行数等）
    - 验证结果（如启用）
    - 优化建议（如适用）
  - 支持不同的结果格式选项
  - 大数据量结果支持分页
- **优先级**: P0
- **验收标准**:
  - 响应格式符合 MCP 协议
  - 大数据量查询支持流式响应
  - 响应时间 < 1 秒（结果格式化）

#### 2.5.2 错误处理与反馈
- **需求编号**: FR-010
- **需求描述**: 全面的错误处理和用户反馈
- **详细说明**:
  - 错误分类：
    - 配置错误（数据库连接失败）
    - 语法错误（SQL 生成失败）
    - 执行错误（查询失败）
    - 安全错误（查询被拒绝）
    - 超时错误
  - 每种错误类型提供：
    - 清晰的错误消息
    - 可能的解决方案
    - 错误码
  - 记录详细的错误日志
- **优先级**: P0
- **验收标准**:
  - 所有错误都被正确捕获和处理
  - 错误消息对用户友好
  - 错误日志包含足够调试信息

## 3. 非功能需求

### 3.1 性能要求
- **响应时间**:
  - SQL 生成：平均 < 3 秒，P99 < 10 秒
  - 查询执行：平均 < 2 秒，P99 < 30 秒
  - 端到端：平均 < 8 秒，P99 < 45 秒
- **吞吐量**: 支持 100 QPS
- **并发连接**: 支持 50+ 并发查询
- **资源消耗**:
  - 内存：单个查询 < 500MB
  - CPU：正常负载 < 50%（4 核）

### 3.2 可用性要求
- **服务可用性**: > 99.9%
- **故障恢复**: 自动重启 < 30 秒
- **优雅降级**: Kimi-K2 API 故障时，提供基础 SQL 生成功能

### 3.3 安全性要求
- **SQL 注入防护**: 100% 拦截恶意 SQL
- **数据访问控制**: 只读访问，无数据修改权限
- **敏感信息保护**: 配置文件加密、日志脱敏
- **网络安全**: 支持 TLS/SSL 连接

### 3.4 可维护性要求
- **代码质量**: 测试覆盖率 > 80%
- **文档完整性**: API 文档、部署文档、运维手册
- **监控能力**: 完整的监控指标和告警
- **升级平滑**: 支持零停机升级

## 4. 用户场景

### 4.1 数据分析师查询数据
**场景描述**: 数据分析师需要从数据库中查询特定数据，但不熟悉 SQL 语法

**用户输入**: "查询上个月销售额排名前 10 的产品，包括产品名称、销售额和销售数量"

**系统响应**:
1. 接收自然语言查询
2. 分析 schema，识别相关表（products, orders, order_items）
3. 生成 SQL：
```sql
SELECT
    p.product_name,
    SUM(oi.quantity * oi.unit_price) as total_sales,
    SUM(oi.quantity) as total_quantity
FROM products p
JOIN order_items oi ON p.product_id = oi.product_id
JOIN orders o ON oi.order_id = o.order_id
WHERE o.order_date >= DATE_TRUNC('month', CURRENT_DATE - INTERVAL '1 month')
    AND o.order_date < DATE_TRUNC('month', CURRENT_DATE)
GROUP BY p.product_id, p.product_name
ORDER BY total_sales DESC
LIMIT 10;
```
4. 执行查询并返回结果
5. 验证结果符合用户意图

### 4.2 多表关联查询
**场景描述**: 用户需要进行复杂的跨表查询

**用户输入**: "找出每个客户的最新订单及订单详情"

**系统响应**:
1. 识别需要关联的表：customers, orders, order_items, products
2. 生成包含子查询和 JOIN 的复杂 SQL
3. 优化查询性能（使用合适的索引）
4. 返回结构化的结果

### 4.3 查询结果验证
**场景描述**: 用户查询数据后发现结果异常

**用户输入**: "统计每个部门的员工平均工资"

**系统响应**:
1. 生成并执行 SQL
2. 发现某些部门的平均工资明显异常（如 NULL 或极端值）
3. 使用 Kimi-K2 验证结果
4. 提示用户："部分部门可能没有员工数据，建议检查数据完整性"
