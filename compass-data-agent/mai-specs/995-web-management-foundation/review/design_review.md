## 本轮关键发现

### D01 / P1：权限收窄后仍返回 200，旧请求和页面数据没有明确失效路径

**证据。** [代码设计 §6](../design/CODE_DESIGN.md#6-原型框架与客户端失效) L499–509 只比较请求发起时的 `epoch` 和 abort 状态；L517 明确在切换上下文或 401/403 时 reset。L522–529 的会话复验在有效响应时直接安装新 `authzVersion` 并取数据，没有定义版本改变时的 reset、清除和重新开放条件。[会话契约](../design/ROUTES_AND_API.md#41-登录本人和导航) L187 返回当前身份与权限，个人权限被部分收窄后会话和租户成员仍可有效；因此不能依赖 401/403 触发清屏。主方案 L146–148 的清屏目标正确，代表性状态机尚未完整落实它。

**触发与影响（基于当前设计推演）。** 用户原先能读取 A、B 两个空间的审计，在聚合审计页发起旧查询；管理员收回 B 的权限，保留 A 和安全模块入口。随后 `/session` 以 200 返回新授权版本，新查询只包含 A。若旧查询最后返回，当前 `RequestScope` 仍可能接受它，把 B 的结果再次填回。即使没有迟到响应，若新查询失败而页面继续展示旧 DTO，复验成功会持续延后遮蔽期限，30 秒清除失权视图的承诺也没有保证。这里的问题是前台局部撤权后的数据替换，不要求撤回用户此前已知的信息。

**最小修正。** 在状态机中明确：成功复验发现用户、会话身份或 `authzVersion` 变化时，先遮蔽并禁写、reset 请求世代、清理敏感 DTO/草稿，再重新核验当前页面和获取数据；只有与当前身份、上下文及授权世代一致的新结果可以解除遮蔽。会话复验响应本身也须受世代/顺序约束，晚到的旧心跳不能把授权版本装回去。不必为此增加推送服务、权限快照表或通用缓存框架。

同一约定须覆盖 RSC。当前方案让 RSC 直接调用查询用例（主方案 L108、代码附录 L431），自定义 `RequestScope` 无法自动控制 Next 路由恢复的服务端组件载荷。应明确选择并实现“遮蔽后刷新当前路由，等待新授权世代的数据”或适合本期的受控整页重新导航；历史恢复不能在会话复验成功后直接重新展示旧 children。已核对安装版 Next 16.4.0 的 `use-router.md` L46–50：`router.refresh()` 会合并 RSC 并保留未受影响的客户端状态，单独刷新不能代替敏感状态清除。在线 [Next useRouter 文档](https://nextjs.org/docs/app/api-reference/functions/use-router)同样说明了该行为；版本依据以本地安装文档为准。

**关闭验证。** 在既有 T07/T11、V05、AC-995-42/44 内补充明确反例：只撤 B 且 `/session` 仍为 200；旧查询晚于新查询；旧心跳晚于新心跳；刷新数据失败；另一标签页切换登录身份；返回此前访问的 RSC 页面。验证新请求范围正确、旧结果不重新入屏、失权内容在约定期限内清除、恢复时无旧内容闪现。当前报告完成的是设计推演，这些浏览器场景尚未执行。

### D02 / P2：审计导出需要明确区别于普通只读查询的事务顺序

**证据与待验证假设。** [主方案 §1.5](../design/TECH_DESIGN.md#15-一致性查询与集成) L106 统一要求查询用例使用同一有界只读快照；[导出契约](../design/ROUTES_AND_API.md#43-总览与审计) L243–245 又要求生成 CSV 并写入 `generated` 审计。当前未说明导出用例选择哪种事务、何时提交审计和开始响应。若实施直接复用 SQL `READ ONLY` 事务并在其中写审计，PostgreSQL 会拒绝该 INSERT；若先发送 CSV 再异步补审计，审计失败后已无法收回成功响应。[PostgreSQL 17 SET TRANSACTION](https://www.postgresql.org/docs/17/sql-set-transaction.html)明确区分隔离级别和只读模式，`READ ONLY` 禁止向普通表写入。

**建议。** 在 T09 的 `exportAudit` 用例补一段顺序即可：当前授权与有界查询 → 完整生成并校验 CSV 限制 → `generated` 审计提交成功 → 返回文件；失败不发送成功文件。可用具有一致快照的读写事务承载查询与审计，或明确分段事务及失败约定；保持 10000 行/10 MiB 上限，不增加后台导出任务或回执表。普通分页查询同时明确“同一快照”的数据库实现，避免只设置 `READ ONLY` 后误用默认 `READ COMMITTED` 的逐语句快照。

这是实施接入风险，当前没有已证实的导出实现故障。建议在 T09 开始前写清约定；复用 AC-995-30/36 增加审计插入失败不返回 CSV、超限不截断、列表/计数共享快照的验证。无需因本项创建独立设计或测试体系。

# Feature 995 数据结构与教学复杂度评审

> 日期：2026-10-25 · 评审者：Codex · Profile：`standard` · 结论：**需要修改**
>
> 本轮对象：[数据设计](../design/DATA_DESIGN.md)，并核对[主方案](../design/TECH_DESIGN.md)、[代码设计](../design/CODE_DESIGN.md)、[页面/API](../design/ROUTES_AND_API.md)和[PRD](../spec/PRD.md)。这是针对教学必要性与过度设计的专项评审，未作完整安全审计或运行验证。按既有报告增量维护，不另套模板。

## 1. 本轮结论

**建议将本期 Web 模型从 17 张业务表收敛到 8 张，移除企业 SSO 和通用授权平台的前置依赖。** 重点保留真实身份、服务端会话、租户/空间隔离、简单角色、管理 CRUD 和必要审计，让后续 Agent 的权限、数据与执行链路有可用基础。

前一版在用户要求的“Web 工程基座”中放入了较完整的身份与组织治理能力；其中组、邀请、动态角色等又被写入 PRD，造成设计和需求互相支撑，却缺少教学收益的再次检验。本轮应同时收敛需求与设计，不能只删除表后仍声称全部旧 AC 满足。

用户本轮明确要求判断教学 DataAgent 中不必要的复杂度，并提出“比如：Oauth的用户体系，我觉得必要性就不大”。当前具体设计是 OIDC/Keycloak 登录。OIDC 用于认证，建立在 OAuth 2.0 之上；本轮建议延后的是这套企业身份接入，基本用户与会话仍保留。[协议依据](https://openid.net/developers/how-connect-works/)

判断依据：当前[课程定位](../../../../../../course/positioning/course_positioning_and_design_goals.md)强调核心 Agent 工程能力和控制平台化复杂度；[V5 大纲](../../../../../../course/curriculum/v5/course_outline.md)明确需要多租户、工具权限、受控执行及恢复能力。由此推断，隔离与执行约束有直接教学价值；在本期尚无真实企业 IdP 接入要求的情况下，SSO 的部署与协议联调可以后移。此结论不否定后续真实企业或远程 MCP 接入中的标准认证需求。

本轮发现 3 项 P1、4 项 P2，无已证实 P0。8 表方案是供负责人选择的收敛建议，尚未替换有效 PRD/设计。Feature Phase、ROADMAP、生产代码保持原状；下方旧 PRD 评审保留为历史记录，不能据其“通过”直接实施当前重方案。

## 4. 登录替代方案与不可删的边界

推荐“教师初始化账号 + 用户名密码登录 + Web session”，本期只交付登录、退出、本人会话撤销和受管密码重置；不加入公开注册、短信、邮件验证、找回密码邮件或账号联邦。这样删除 IdP 运维依赖，同时保留可测试的真实用户身份。密码使用成熟实现的 Argon2id 等密码哈希，不能明文或可逆加密保存；参数和库由实施时固定验证。[OWASP 密码存储依据](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)

本地登录仍需最小登录限速、通用错误、HttpOnly 会话 cookie、共享环境 HTTPS、Origin/CSRF 校验与密码重置后会话失效。创建账号/平台资格仅受管操作；租户管理员可把已存在账号加入自身租户，不能读取或修改全站密码。未来接企业 SSO 时保留 user_id，把外部身份映射加在认证入口，业务表无需改用 issuer/sub。

仅本机演示可另设显式开发登录开关，但不建议把前端角色切换当默认登录，更不能据其通过多人权限验收。采用本地账号也会产生密码处理职责，上述成熟哈希与最小防护属于替代成本，应一并计入。

以下能力保留，有当前教学目标或已确认验收依据：

- 租户隔离、同租户关系约束、范围下推，搜索/列表/计数/导出和直接 ID 使用同一授权语义；Web 的 tenant_id 不直接假定等于零售库租户键。
- 服务端当前权限校验、会话撤销、最后管理员的事务保护；固定角色只简化判定，不解除这些不变量。
- Web 独立持久化与 app 所有权、PostgreSQL 真库验证、参数化 SQL、必要唯一/FK/事务/版本冲突检查。
- Web 审计及敏感字段白名单；迁移与运行账号分离、真实 SQL 交付与恢复。审计的固定保留期是部署默认值，不能扩成通用治理平台。
- 原型全部导航、页签、布局、配色及反馈；高级身份/组/服务身份能力延期时，其界面有明确说明，不能出现可提交的假成功按钮。
