# 行野运动集团业务文档证据包

23 篇中文合成业务文档，覆盖 12 类资料与 Compass 的 S01–S12 分析故事。正文采用业务档案、制度、计划和通知文体；精确事实绑定 998 的 `diagnostic-v3-20261019`。文档用途、来源与假设在机器目录中单独保存。

本目录为冻结正文及生产配置的唯一维护源。`build.py` 只校验、定位引用和导出，不调用模型重写正文。导出包位于工作目录，属于派生交付；修改正文后须形成新候选及版本，不能静默替换已交付包。

## 阅读与使用

- `documents/D01.md` 至 `D23.md`：7 篇扩写、16 篇新编正文。
- `catalog.json`：文档版本、适用业务、证据作用、同源关系、时间和权限元数据。
- 源目录的 `sources.json`，交付包的 `sources/evidence.json`：原始文件摘要、精确业务键、源行及口径摘录。属于追溯资料，不进入业务正文索引。
- `citations.jsonl`：导出生成的原句定位，含版本、段落、行号、字符区间及源引用。
- `chunks.jsonl`：导出生成的完整章节片段，是向量接入的唯一索引入口；不要同时把正文与片段重复索引。
- `cases.json`：源目录中的独立演示配置。交付包内为 `validation/cases.json`、`validation/DEMO.md` 与 `validation/report.json`，不进入向量索引。

优先查看采购时间线 D04–D06、补货约束 D07、数据延迟与补齐 D14–D15、实验预案 D16–D17、财务对账 D18，以及身份与留存 D20–D21。活动与调价资料 D08–D10、平台分母说明 D22 用于交叉检查转化解释。

## 时间与证据约定

`authored_at` 是本次真实整理时间；`business_known_at` 是有源记录支持的业务可知时点。事件重建文档不冒充当年存在的签章原件；它证明的是原记录当时可知的事实。

部分商品和口径资料缺少历史签发日期，`business_known_at` 保留空值，只作当前参考，不用于证明更早时点“已经正式发布”。新增责任岗位、核单及留档步骤属于明确标识的模拟业务规程。D07 的专项 50 件保留量是模拟经营约束，历史签发时间未知；原 35 / 21 天备货规则另有 2023 年原件。

如按历史知识截止检索，排除尚不可知的文档；未来计划还必须覆盖目标预测窗口。现有材料不提供完整事前 12 周计划。普通 diagnostic 的分钟支付样本不足，正文不添加确认故障公告。

`origin_group` 标记同一业务过程的派生资料，`derived_from` 指向原始来源。采购原安排、延期和到货均属于同源记录，引用三篇不等于三次独立核验。更细的来源交叉关系以共享 `source_ids` 为准。

## 引用契约

引用链为：原句 → 文档版本 → 章节 / 段落 → 源记录或口径 → 998 发布版本。字符位置为 Unicode 码点的左闭右开区间，哈希按 UTF-8 原文计算。引用保留完整段落；表格作为整体段落保留表头。

章节片段继承租户、访问范围、知识时点、来源和模拟规程标记。当前元数据核验只验证内容契约；生产系统仍须在检索、正文展开、摘要与引用显示时实施授权。

## 校验与导出

在 Compass 根目录执行，Python 3 标准库即可运行：

```bash
python3 mai-specs/996-rag-knowledge-document-seeding/corpus/build.py \
  --source work/data-seed/diagnostic-v3/delivery-main \
  --output work/rag-documents/996/rag-documents-996-20261024
```

省略 `--output` 仅校验源与正文。导出先核验源包、正文、引用和独立反例，再写新目录；已存在的同版本包只允许逻辑摘要完全一致的重放。校验失败不替换既有包。

在只收到交付包的环境，可直接阅读文档、目录、引用和所带源记录摘录；核对完整原始文件仍需对应 998 包。原始 SQL 使用逻辑 `core / ops` 名称；学员导入库统一映射到 `retail_course` 下同名表，避免把逻辑名称误作实际 schema。

内容核验、案例引用定位和源记录核验不代表 embedding、召回率、在线授权或完整 Agent 结果已经验证。后续检索只消费允许的正文片段，保留验证目录与来源摘录的索引隔离。
