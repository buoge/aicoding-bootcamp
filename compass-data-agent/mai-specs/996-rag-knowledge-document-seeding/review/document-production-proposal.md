# Feature 996 文档生产建议清单

> 日期：2026-10-24 | 状态：review | 来源：[PRD 评审报告](design_review.md)
>
> 本文是评审建议，尚未替换 [PRD](../spec/PRD.md)。数量是待生产目标，现有业务原件和 998 事实保持原样。本轮尚未生成以下正文。

## 1. 生产规模与计数

建议首批主包生产 **23 篇逻辑文档、23 份首版冻结正文**，全部服务行野运动集团（tenant 101）的现有分析故事。其中 **7 篇扩写现有业务短文，16 篇依据结构化事实、冻结商品资料及可登记的业务设定新编**。

“新编”指新增文档表达，不表示新增或改写交易事实。资料类型、引用字段和例外足以满足本轮需求，无需同步建设完整检索服务。

| 计数对象 | 本次数量 | 计数边界 |
|---|---:|---|
| 核心逻辑文档 | 23 | D01–D23，一行一篇；一篇可服务多个故事 |
| 首次冻结的正文版本文件 | 23 | 每篇首版各一份；未来有真实修订需求再追加 |
| 对既有短文的扩写 | 7 | D07、D08、D11、D14、D15、D19、D20；计入上述 23 篇 |
| 新编正文 | 16 | 其余文档；来源仍必须可追溯，计入上述 23 篇 |
| 既有场景短文原件 | 10 | 保持原样用于来源追溯，不加进新生产数量，不默认全部索引 |
| 额外历史规则版本、对照租户、demo 故障正文 | 0 | 本次核心包不为测试配额新造资料；需要时独立列扩展清单 |

分段数量、PDF 或 HTML 导出、目录、核验记录、评测问题均不计为业务文档篇数。23 篇的数量来自所需业务证据组合；不要求每条 S 场景各有一套独占资料。

## 2. 每篇都应满足的内容要求

每份正文包括自然业务标题、责任部门或形成主体、文档类型、适用对象、时间、主体内容和来源说明。规则型写清适用条件、例外和执行边界；计划型写清目标、范围、时间及假设；记录型写清发生或获知了什么、对象是谁、后续有何更新。

正文使用正常企业文体，既不放生成器参数或评测答案，也不堆砌 Agent 实现术语。文档篇幅由业务内容完整性决定；不能以一段通用背景介绍交差，也不为字数补写无来源的原因。

生产目录另外为每篇记录：

- 对应的分析故事、比查询结果增加的业务信息、证据作用；
- 可支持的判断、不能证明的结论、必要的后续结构化查询；
- 业务源版本、实体键、来源材料或记录、同源分组；
- 正文版本、引用定位、适用范围和访问范围。

源类型须区分：已有源材料的派生、数据库记录的可读转述、合成制度 / 计划设定。数据库派生记录不能称为独立外部证据；新增合成设定可以约束模拟世界，但不能反过来证明实际效果。

D04–D06 分别保留采购原安排、修订通知和执行记录，新增价值是三个时点的可引用记录及其关联时间线，不增加独立事实。三篇分别限定可知时间，不能将收货结果提前写入原安排或延期通知。无需为了制造“增量”编造原因；普通经营数字汇总改写为段落不单独计篇数。

## 5. 引用与溯源要求

最小链路为：**分析结论或假设 → 引用原句 → 文档版本与章节 / 段落 → 来源材料或业务记录 → 998 release 与可知截止。**

| 信息 | 最小要求 | 验收方式 |
|---|---|---|
| 文档定位 | document_id、version_id、标题、相对源路径、原文哈希 | 能打开完全相同的原文版本；后续修订不改变旧引用 |
| 引用定位 | 稳定section_id / paragraph_id、引用原句、起止位置或片段哈希 | 定位后的原句与原文一致，能展示上下文、表头和例外条款；不能仅返回文件名 |
| 业务定位 | tenant、业务release/profile、相关SKU / 门店 / 采购 / 活动 / 实验键 | 引用实体确实存在且不跨租户、商品、渠道或业务期误用 |
| 时间定位 | 原记录 / 发布可知时间、事件或生效时间、必要有效期、实际文档生成时间 | 区分模拟业务时间和现在的生产时间；不以新资料回答历史“当时已知”问题 |
| 来源定位 | 原件ID/路径与哈希；数据派生资料保留表名、业务键与冻结快照 / 受控查询引用 | 每个关键事实可复核；原始材料无定位时不能标为已证实事实 |
| 同源关系 | origin_group / derived_from及来源类型 | D04–D06和采购数据按共同来源识别，不当成独立供应商访谈或外部核验 |
