## 1. 结论

PRD 已有事实一致性、版本时效、租户范围和原文引用基础，但尚未给出可直接执行的文档生产清单。真实 embedding、向量库导入和检索质量被绑定到文档发布，扩大了当前需求的交付范围。建议先将 996 收敛为“分析所需业务文档数据的生产与循证引用”，按 [23 篇核心文档清单](document-production-proposal.md)明确内容交付，再独立验收生产 RAG 接入。

每篇文档须回答四件事：它比结构化查询多解释什么、能支持或限制哪个判断、不能证明什么、引用能追溯到哪个版本与原始来源。数据库派生文档与其对应查询属于同源证据，不能因表现形式不同而被计为独立佐证。

本次没有 P0。以下 P1 需要在安排正文生产前修正；评审结论不等于业务批准。

## 4. 建议保留与删减的范围

保留：已批准规则与来源核对、业务时点与可知时点、租户和适用范围、正式版本不可变、正文及引用位置、计划和结果区分、禁止私有答案进入语料。

优先补齐：逐篇清单、关系型数据之外的补充价值、同源关系、反证与限制说明、可核对的原句引用、故事中允许输出证据不足的条件。

建议后移到接入阶段：embedding 选型、向量库构建、Recall@5 指标、在线过滤与动态撤权、导入失败恢复和全量多租户检索回归。本阶段交付相应元数据和可导入文件，接入验收继续必须真实执行，不能用文档检查冒充。

不额外凑数：完整未来 12 周计划、无来源客户访谈 / 质量事故 / 商圈变化、虚构合同或审批、为测试专门编造的制度变更。其他租户及 demo 材料作为单列扩展，不计入核心业务正文数量。

## 5. 收敛后的交付判断

[生产建议](document-production-proposal.md)固定主包 23 篇逻辑文档、23 份首版正文：7 篇扩写已有业务短文，16 篇依据实际数据和可登记业务设定新编。7 篇派生版使用自己的文档标识并保留 derived-from 来源，不能自动把原短文改名为同一文件的历史批准版本。

当前所需验收是：23 篇是否具备明确的业务补充价值、全部关键事实是否可核对、每次引用是否可定位原文版本和原始来源、同源资料是否被正确标识、缺少证据时是否保留缺口。语义检索能否稳定返回它们由后续接入验证回答。
