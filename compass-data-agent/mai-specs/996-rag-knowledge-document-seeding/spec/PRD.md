## 1. 背景与目标（Why）

### 1.1 背景与已核验事实

Compass 服务虚构的全渠道运动户外企业行野运动集团，以及用于租户隔离验证的越岭户外、潮跃运动。998 已提供商品、订单、支付、退款、库存、采购、流量、投放、身份与经营目标等事实，999 定义了 S01–S12 分析场景。经营问题还需要正式制度、指标口径、商品档案、批准计划和业务通知，帮助用户理解数字、核对事件及判断行动约束。

[998 当前交付](../../998-business-data-seeding-tool/IMPLEMENTATION.md)为 `diagnostic-v3-20261019`，业务命名空间 `retail_v3`，共 71 张关系表、111,055 单、160 SPU、1,280 SKU。学员 SQL 映射为 `retail_course` 并内嵌 27 份公开材料，其中包含参考 SQL、字典、清单、结构化附件及短篇运营说明。现有材料不能整体作为正式业务知识入库；`public` 仅是业务包分发分类。正文核查与源侧实现见 §8。

评审已核验其中 10 篇业务场景短文，含元数据仅 146–280 个字符。本版扩写其中 7 篇；支付样本说明保留为使用资料，收入观察保留为同源快照，2026-03-31 商品摘录保留实际可知时间，三者均不另计新生产篇数。原始材料保持不变。

普通 diagnostic 的分钟支付样本不足，高密度支付监控采用独立 demo profile。本需求必须遵循这些事实边界。编写文档不能补造已发生的故障、审批执行、客户投诉或因果结论。

### 1.2 目标与交付结果

生产与 998 同一业务世界的 **23 篇中文合成企业文档、23 份首版冻结正文**，包括 7 篇扩写与 16 篇新编。文档补充关系型数据中的业务定义、经营意图、过程时间线和行动约束，服务 S01–S12 分析故事；逐篇名称、内容、来源及使用边界见 §4.2。

每篇资料须说明：增加什么业务理解、支持或限制哪个判断、仍需查询什么、引用如何回到原句及原始来源。文档不预置分析答案；实际数值、影响量和因果判断继续由结构化查询及分析承担。同源记录不能因转写成文档而成为独立佐证。

本阶段交付冻结正文、机器可读目录、引用与来源映射、内容验证材料及使用说明；可附派生 JSONL 片段。内容验收通过可以完成 996 文档数据交付。向量导入、embedding、召回质量、在线权限和 UI 属于后续接入验收；未执行时如实标记，不阻塞已合格语料的内容发布，也不能宣布 RAG 已上线。

## 3. 总体业务流程

### BF-01：生产并交付文档数据包

参与者为语料维护者、文档生产工具及业务审阅者。输入为冻结的 998 数据包、已登记事实源与本 PRD；输出为通过验收的文档发布包及独立验证报告。

1. 选择 release / profile 和业务时点，核验源清单与摘要，生成既有材料分类及故事覆盖清单。
2. 把可查事实、已存在规则和需要补充的合成经营设定分开登记，按 D01–D23 编写候选文档，并登记证据作用与同源关系。
3. 校验实体、时间、金额、规则一致性、适用范围与版本关系。缺证据或存在矛盾时记录缺口，停止受影响文档进入发布包。
4. 审阅正式正文及与材料类型相符的形成 / 发布记录，批准候选语料。修正产生新候选；已发布内容保持不可变。
5. 导出原文、目录、版本、来源与引用记录、使用说明；可附派生片段。核验问题、参考证据和负例独立保存，不进入正文索引。
6. 离线核验正文、源绑定、引用原句、时效及范围标注，完成 §9 的内容验收后发布。失败候选保留供排查，原发布包继续可用；后续真实导入检索的结果单独登记。

### BF-02：修订与历史查询

维护者针对有来源的新规则或事件提交新文档版本，记录替代、撤销及其可知时间，再产出新的不可变包。接入者按新包更新派生索引。历史查询按业务时点和知识截止选择当时可用的版本；当前查询排除已知失效或撤销版本；版本比较可显式返回历史版本及状态。撤销和纠错由新记录表达，不能重写旧包掩盖历史。

#### 4.2.3 通用正文与用途要求

每份正文包括自然业务标题、责任部门或形成主体、文档类型、适用对象、时间、主体内容和来源说明。规则型写清适用条件、例外和执行边界；计划型写清目标、范围、时间及假设；记录型写清发生或获知了什么、对象是谁、后续有何更新。

正文使用正常企业文体，既不放生成器参数或评测答案，也不堆砌 Agent 实现术语。文档篇幅由业务内容完整性决定；不能以一段通用背景介绍交差，也不为字数补写无来源的原因。

生产目录另外为每篇记录：

- 对应的分析故事、比查询结果增加的业务信息、证据作用；
- 可支持的判断、不能证明的结论、必要的后续结构化查询；
- 业务源版本、实体键、来源材料或记录、同源分组；
- 正文版本、引用定位、适用范围和访问范围。

源类型须区分：已有源材料的派生、数据库记录的可读转述、合成制度 / 计划设定。数据库派生记录不能称为独立外部证据；新增合成设定可以约束模拟世界，但不能反过来证明实际效果。

D04–D06 分别保留采购原安排、修订通知和执行记录，新增价值是三个时点的可引用记录及其关联时间线，不增加独立事实。三篇分别限定可知时间，不能将收货结果提前写入原安排或延期通知。无需为了制造“增量”编造原因；普通经营数字汇总改写为段落不单独计篇数。

复用 998 原文时保留原件路径及摘要，扩写正文取得自己的稳定文档标识并记录派生关系。原短文不自动成为扩写版的历史批准版本，也不修改原文件。

|---|---|
