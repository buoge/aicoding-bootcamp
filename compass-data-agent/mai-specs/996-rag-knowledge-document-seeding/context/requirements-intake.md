# RAG 业务知识文档生产：需求输入记录

记录日期：2026-10-24。来源：本次用户会话、Feature 998 当前交付、Feature 999 当前 PRD 与相关源码。本文件保存创建需求时的输入及判断；正式需求与验收在后续 PRD 中维护。

## 用户诉求与本次授权

- 用户要求结合 998 已生成业务数据和数据分析用户故事，创建一个新需求，用于生产将导入向量库、通过 RAG 检索的文档数据。
- 用户随后明确：创建完成后使用 my-create-prd 完成需求撰写。本次连续授权包括 Feature 初始化和 PRD，不包含生成全部语料、修改数据库、部署检索服务。
- 用户关注具有正式版本、发布、归档和周知属性的企业文档，明确提出政策文件属于候选，并询问经常变化或过时内容是否应算事实。
- 会话中已讨论：规则的有效期、正式计划与执行事实、分析判断与已验证结果须区分；过期文档可作为历史依据，当前查询不能无条件使用旧版本。这些是本轮需求的设计依据，具体验收由 PRD 明确。

6. [999 技术方案](../../999-compass-product-course-landing-app/design/TECH_DESIGN.md)已规划文档与向量检索，平台接入仍由 999 管理。本需求以文档数据生产、可导入交付包和验证材料为边界，避免另建平台权限或 Agent Runtime。

## 建议纳入的文档范围

- 已发布制度、SOP、指标与身份口径说明。
- 正式商品档案、商品上市与替代计划。
- 已批准的活动、采购、补货、调拨与价格方案。
- 供应延期、门店营业变更、数据延迟与恢复等正式通知。
- 已确认经营决议及符合当前数据模型的费用、服务约定。
- 每份材料明确语义类型：规则、计划、事件记录；观点与预测需要明确标识。默认正式检索包不收无来源草稿、聊天意见、私有金标和未核实市场情节。

## 业务故事与材料方向

| 故事 | 主要角色 | 文档需求 | 数据关联与使用边界 |
|---|---|---|---|
| 净销售额与财务结果差异 | 区域经理、财务、BA | 指标定义、退款确认、结算与关账说明 | 绑定收入、成本、费用、退款和可知时间，数值由事实查询 |
| 全区域增长但老店下降 | 经营与区域负责人 | 同店口径、开业及营业变更通知 | 绑定 site、store_operating_day；不凭空增加商圈原因 |
| 活动名单与历史会员关联 | CRM、BA | 身份绑定、名单处理及历史识别规则 | 不回填未来身份，保留未识别样本 |
| 热门规格缺货与采购延期 | 商品、供应链 | 商品档案、补货规则、采购延期及调拨要求 | 绑定具体 SKU、地点、采购修订；候选措施与实际执行分开 |
| 转化变化与经营变更 | 电商负责人 | 活动、调价通知、业务变更记录 | 对照 price_exposure、活动、流量与库存；同步发生不证明因果 |
| 数据未齐导致异常 | BA、数据治理 | 数据服务约定、迟到与恢复公告 | 绑定业务期完整度及 available_at，不能用公告覆盖源事实 |
| 未来 12 周销量规划 | 商品负责人 | 已发布上市、促销、补货计划 | 只使用预测时已知计划，未来实际值留在评测侧 |
| 活动转化与退款护栏 | 市场负责人 | 实验预案、指标护栏、售后规则 | 预案应在实验前已知，不能按结果倒写标准 |
| 涨价与流失研究 | 经营负责人 | 调价决议、适用范围、同期经营安排 | 沿用观察性研究识别限制，文档不预埋因果答案 |
| 支付成功率监控 | 运营、运维 | 尝试口径、监控处置 SOP、适用 profile 的事件通知 | diagnostic 与高密度 demo 分开；无证据不生成确认故障公告 |
| 周期报告与留存看板 | BA、CRM | 周报口径、数据就绪规范、成熟队列规则 | 保留截止时间、范围和身份，授权由产品执行 |

## 建议交付与判定方向

- 中文可读正式文档、文档及版本目录、向量导入所需元数据与正文片段、来源与校验信息、使用说明。
- 发布正文不可静默覆盖；修订形成新版本，保留替代关系、发布与生失效时间、撤销记录。
- 业务发生、生效、发布可知、真实生成时间分开；合成企业时间线不冒充真实企业审批记录。
- 绑定 998 release、业务实体键与证据；价格、数量、金额、日期从已有事实核验。未覆盖事项登记缺口，不擅自修改 998 迁就文档。
- 按岗位故事检查有效文档覆盖和可引用性；文档主体应保持企业文体，不出现评测答案、生成器参数或要求 Agent 得出指定结论的提示。
- 检索正反例覆盖历史版本、未来发布、过期或撤销、范围错配、跨租户、同名商品、证据不足及文档中的指令文本。
- 文档导入准备完成与真实向量检索通过分别报告；后续实现需给出当前可执行的验证路径，不能仅凭文件齐全宣称检索质量达标。

## 留给 PRD / 技术设计的收敛项

- PRD 定义首批必须覆盖的故事和文档家族；篇数依据覆盖与版本需求确定，避免仅凑数量。
- 以 998 当前 diagnostic 为主包，demo 只承担独立监控扩展；源包版本和摘要最终由交付清单锁定。
- 文档生产可使用模型辅助撰写，精确字段来自业务基线；模型、切片参数、向量适配方案由技术设计确定。
- 999 已有 PostgreSQL / pgvector 的规划应作为接入参考，不把厂商选择当成此次需求创建的前置阻塞。
