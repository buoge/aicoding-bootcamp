# home 官网 App 首版设计

状态：review · 日期：2026-10-20。补充 [TECH_DESIGN.md](TECH_DESIGN.md)，需求与验收唯一来源为 [PRD 第 21 节](../spec/PRD.md#21-home-官网首版)。保留现有 DataAgent 架构和 Feature Phase。

## 需求依据与切片

用户明确创建独立 `home` App，使用 React、TypeScript、Next.js 和 shadcn/ui。首页用于产品营销，另五页按 [landing_page_prd.md](../context/landing_page_prd.md) 展开；本次按列出的六页实现。首页首屏使用指定 `@react-bits/GhostFibers-JS-CSS`，沿用 Compass 绿色设计体系。

## 实现与依赖

- 源码放 `apps/home`，包名 `@compass/home`，独立端口 3001；根 pnpm / Turborepo 自动识别，无跨 App 源码引用。
- App Router 的六个页面保留服务端渲染边界；只有动画、导航抽屉、筛选、切换、复制与浏览器进度使用客户端组件。没有新业务 API、数据库表或登录入口。
- `content.ts` 维护页面所需的课程任务结构；类型 `CourseTask` 固定编号、类别、课次、讲师输入、学员实现、依赖、验收证据和建议范围。任务总账从数组计算，筛选和 CSV 使用同一结果集。
- 产品页九类岗位使用表格，经营复杂性用 Tabs，课程情节用带选中状态的按钮；系统架构区域直接使用 [system-architecture.png](../context/dataagent-tech-stack/visuals/system-architecture.png)，按比例完整展示并通过链接打开原尺寸；任务类别用单选 ToggleGroup；明细 / FAQ 用 Accordion；移动导航用带标题的 Sheet；复制、导出和状态按钮有明确反馈。
- 学习进度保存在 `compass-home-readiness-v1`，通过 `useSyncExternalStore` 读取；内容损坏时恢复空列表，存储受限时保持当前页面内可操作并说明限制。
- 原型的唯一编辑源继续是本 Feature 的 `design/prototype/`。准备脚本分发原型 HTML / CSS / JS，以及指定架构 PNG；原图保留在 `context/`，不修改图片。重建前清理原型派生目录，避免删除过的文件残留。构建缓存显式纳入原型、架构图输入和对应副本输出。
- 默认生产运行用 `next build` + `next start`。私有 Sites 预览使用同源代码的静态导出。发布在隔离目录内构建，原型快照纳入发布源；不推送课程完整仓库。在同一目录切换静态导出与服务端运行时，需要重新构建。

## 视觉与性能

品牌 Token 使用 [设计体系](ui-ux-design-spec.md)。首页深绿背景，GhostFibers 点状光纤使用薄荷绿与青绿色；内容采用暖白、墨绿、细分隔线、宋体叙事标题与系统正文，减少外部资源依赖。

产品页按用户更新采用 Apple 产品介绍页式纵向叙事：一屏聚焦一个主题，暖白、浅绿与深绿段落交替，右侧圆点导航悬浮，不占正文宽度。架构与脚手架页使用同一纵向分屏模板，分别按三主题、七主题组织。课程、学习页保留紧凑页眉、页内目录、可引用的章节号和下一页；移除装饰英文、大号页码与重复页序。架构图放在架构页第三屏；完整启动步骤在脚手架末屏展开。任务查询、开工清单保持前置。小屏复杂图转单列，产品岗位表转为逐行阅读，其余复杂表格在容器内滚动。深绿也用于产品页经营复杂性段，不增加独立主题状态。

顶部导航去掉底部 border。滚动距离严格大于导航栏实测高度后（桌面 80 px，小屏 68 px），实色底层与玻璃层通过 180 ms 透明度过渡切换；玻璃采用半透明色、18 px 背景模糊、160% 饱和度、渐变高光及柔和投影。首页使用深绿玻璃，内容页使用浅色玻璃，滚动前后高度保持一致。滚动与窗口尺寸变化订阅读取实际导航高度，仅在布尔状态变化时触发 React 更新；SSR 提供稳定初始值。不支持背景模糊或用户偏好减少透明度时显示实色背景，减少动画偏好沿用全局过渡规则。

GhostFibers 动态加载，仅首页使用；保留原生视区 / 页面可见性暂停与减少动态效果支持，增加显式暂停按钮和渐变降级。最高 DPR 1.25，减少高分屏填充开销。第三方 JS-CSS 版本按用户要求保留，业务代码使用 TypeScript。

## 当前设计的模板感与改进方向

2026-10-20：用户确认实施上一轮建议，本节记录改动依据与已落地结果。目标受众为中文电商团队与课程学员，保留正式课程名称、技术术语、任务编号和当前能力边界。

调整前的页面有较明显的模板化营销感。重复的装饰语言和整齐划一的标题节奏，削弱了 Compass 自身的业务特征。英文只承担装饰用途时尤其明显；API、SQL、Agent、MCP、Next.js 等名称仍然有准确表达的作用。此判断用于改进体验，不用于推断内容的生成来源。

| Before | After（已实施） | Why |
|---|---|---|
| `THE ENGINEERING`、`COMPASS FIELD GUIDE`、`YOUR STARTING LINE` 等大写英文重复中文标题 | 删除不提供新信息的英文；需要分类时直接写“技术架构”“开工检查” | 中文受众无需多读一层装饰；保留技术名称即可 |
| 内容页同时出现大号页码、`03 / 06`、章节 `2.1`；首页有静态 `01 — 06` | 保留目录和有引用意义的章节号；取消装饰页码及容易被误认作进度控件的数字 | 编号应帮助定位；课程课次、任务 ID 继续保留 |
| “一个问题，连起完整的经营现场”“让智能发挥，让系统守住边界”重复采用双句口号 | 内容页直接使用“产品功能”“系统架构”“运行项目”等任务标题；品牌主张集中在首页 | 让访客快速知道这一页能解决什么问题，降低阅读成本 |
| 首页首屏主要表达“数据给你方向”，具体行业与工作成果需要继续寻找 | 首屏明确“面向电商团队的经营分析 Agent”；引用原型 S05 华东收入诊断、S04 指标对账及 S10 日报授权，展示分析过程、可展开的依据与待核验项、报告入口 | 产品识别更具体；演示沿用已标注的合成数据，不编造客户评价、收益指标或成熟能力 |
| 五个内容页共用较大的叙事首屏，内容块经常采用同等留白、三列说明与细分隔线 | 首页保留沉浸首屏；架构页优先展示架构图，脚手架页优先展示启动命令，课程页优先展示任务查询，学习页优先展示开工清单 | 统一色彩、字体和导航，同时让每页的信息密度服务其任务 |
| “可治理、可验证、有据可依”等抽象价值反复出现；示意对话中的结论也较概括 | 每项价值配一个原型中可查看的具体动作：展开证据、打开报告、等待授权或恢复任务 | 用可检查的过程支撑主张；已经存在的原型和指定架构图优先复用 |
| 营销页脚持续展示“产品定义与原型评审中 · M0 工程基线”，并放置设计规范入口 | 面向体验者保留“产品体验原型”说明；M0 状态、设计规范和工程细节集中在课程与开发内容中 | 当前状态保持真实，用户在相关场景中获取所需信息 |

以上调整已实施。课程查询前置，统计说明折叠，六阶段详情保留在查询之后；脚手架保留环境要求、所有启动步骤与排障内容；学习清单的本地保存行为保持不变。首页保留一条品牌主张，墨绿、宋体主标题、指定 GhostFibers 动画和原始架构图继续使用。玻璃效果限定在固定导航等需要覆盖滚动内容的界面，不向正文卡片普遍扩散。

首页案例摘录来自 `design/prototype/scenarios.js` 的 S05、S04、S10，数值均标注为合成数据；诊断只表述渠道贡献和共同变化，不将相关性写成因果。完整执行、审批与报告操作通过对应原型链接访问。营销页脚保留产品原型说明；M0 与待建设范围继续在产品交付、架构和脚手架页面明确列出。设计规范入口归入脚手架的产品参考材料。

### 数据规模与挑战的具体化

架构挑战使用行业定义第六节的既有生成目标：课程云端 1,000 万订单、2,000–3,000 万订单行、1–3 亿行为事件；连续 36 个月、6 万 SKU、240 门店。库存年快照估算为 240 × 3,000 × 365 = 262,800,000 条，约 2.63 亿，未含配送中心。三档规模和八类来源由公共 `DataScaleDetails` 在架构与脚手架数据屏展示，注明生成目标、未测性能与物理表数待定。

并发挑战明确临时分析、周期报表与库存监测竞争；异步挑战明确数据晚到、等待授权与故障恢复；循证归因使用销量、缺码、补货与签收记录链；上下文明确对亿级行为先过滤聚合；权限明确区域、渠道、字段、快照与报告分享。并发数、QPS、时延和预算上限不填未经验证的数字。当前表数通过 `compass_api/database.py` 和 Alembic 迁移核对，为一张 `demo_daily_sales` 示例业务表；数据库迁移工具的元数据表不计入业务表。

导航玻璃底色由 `--header-glass` 统一控制：浅色 `rgba(248,249,246,.82)` / 深色 `rgba(7,27,22,.74)`，确保覆盖深色正文时可读。按用户最新要求恢复该变量及伪元素引用；滚动超过导航自身高度时显示 18 px 模糊与 160% 饱和度的玻璃层，回到阈值以内恢复实色。顶导无底部 border，动态效果降级保持原约定。

### 工程规范的实际落点

工程规范屏由 `engineering-standards.tsx` 展示四个分类：代码与类型、契约与边界、环境与数据、测试与 CI。共十项，逐行对应当前规则、配置文件、命令及检查机制；桌面为三列表格，手机按行转为纵向条目。分类支持键盘切换，人工约定与检查范围、整组命令分别折叠展示。此组件仅做查阅索引，规范定义继续保留在原配置与脚本中。

事实依据涵盖 ESLint / TypeScript、Ruff / Pyright、契约生成与 Ajv 校验、workspace 脚本、版本与锁文件、环境加载和 Turbo 缓存、Alembic 与 seed、Vitest / pytest / Node test，以及课程根目录 `.github/workflows/compass.yml`。路径统一相对 Compass 根目录，课程 CI 因此显示 `../../../.github/workflows/compass.yml`。

检查边界明确呈现：doctor 检查工具可用性并打印版本，不作严格版本比对；两个独立 App 消费才提取共享包由评审落实；当前边界检查只覆盖脚本与 Web ESLint 已配置的范围；API 单测使用 SQLite，PostgreSQL 集成由 CI 容器链路验证。未配置的格式化、覆盖率、提交钩子和浏览器 E2E 门禁不写成已有能力，CI 是否被分支保护强制执行也不作推断。
