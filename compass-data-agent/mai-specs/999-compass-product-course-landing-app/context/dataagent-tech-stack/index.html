项目场景

“华东区 GMV 为什么下降？”

业务用户提出问题，DataAgent 给出可核对的分析过程与结论。

一次经营分析任务

先确认口径，
再解释变化。

地区、时间、指标与数据权限共同决定这次分析能回答什么。

零售经营分析
  1. 01

    确认问题

    明确 GMV 口径、对比周期和可访问的数据范围。

  2. 02

    查询与计算

    使用只读数据源，分解地区、品类与渠道的变化。

  3. 03

    核对证据

    保留查询、计算产物和指标版本，检查结论是否有依据。

  4. 04

    提交报告

    展示结果、限制与调整草稿，供业务负责人复核。

起步版本（M0）只做只读分析和不可变调整草稿；真实业务写入属于后续候选能力。

分层与部署分开理解Next.js UI 与 BFF 同属 apps/web。FastAPI 业务模块留在 API；Harness、Context、Knowledge、Memory 及模型与查询适配先在 Worker 内。Sandbox Gateway 与隔离执行器独立。

本图展示 M0–M5 目标范围，逻辑模块不代表独立微服务。M0 只读分析；Action 写入、扩展应用与 Kubernetes 按后续阶段和实际需要引入。工程工具不属于线上请求链。

分层技术栈

每一层都能找到对应的工程问题

复用成熟基础设施，保留需要学习和验证的 Agent 机制。

层次技术选择在项目中负责什么
01前端与 BFFNext.js · React · TypeScriptTailwind CSS · shadcn/ui · ECharts工作台、会话、页面聚合与流式交互。前端和 BFF 位于同一个 app。
02领域 APIFastAPI · Pydantic · HTTPXOpenAPI → TypeScript 类型与客户端业务授权、任务命令、持久事件。所有操作在服务端检查租户与资源权限。

04可靠运行Temporal · Python WorkerOutbox · 幂等 · 超时与取消长任务恢复与等待。模型、数据库、工具 I/O 放在 Activity 边界。
05数据与计算PostgreSQL · pgvector · S3SQLAlchemy · SQLGlot · DuckDB · pandas业务状态、检索与证据。只读查询受控，生成代码在独立 Sandbox 中运行。
06质量与工程Turborepo · pnpm · uvOpenTelemetry · pytest · Playwright · Eval管理构建、依赖与回归。任务结果、过程、成本和故障恢复分别检验。

按阶段引入依赖：M0 先跑通分析，M2 加入持久执行，后续完善知识、记忆与评测。

Next.js 应用边界

前端与 BFF，
在一个 app 内交付。

Next.js 面向页面和交互，Python 面向 Agent 业务。两者通过领域 API 协作，可分别构建与部署。

apps/web

SSR 按页面需要使用。聊天、图表和筛选保留客户端交互。

一次请求经过哪里Node.js → Python
浏览器→Next.js BFF→Agent API
Next.js 处理
登录会话、页面数据聚合、输入初检、任务提交与 SSE 转发。
Agent API 检查
委托身份、租户成员关系、资源权限、业务状态与幂等键。
Worker 执行
长任务、模型调用、查询与计算。浏览器断开后，任务仍按其生命周期运行。

服务端组件直接调用内部 API client；客户端交互走同域 BFF。取消任务需要独立命令。

Turborepo 管构建，uv 管 Python。

Python app 用私有 package.json 暴露构建和检查任务，运行依赖仍声明在 pyproject.toml。CI 校验两边的内部依赖关系。

共享规则

两个及以上 app 使用，才提取为包。

API 与 Worker 共用 agent-core。只有 Web 使用的组件留在 Web；加入管理端后，再提取共同需要的 UI 和客户端。

扩展方式

新增 app，接入既有任务与契约。

管理端可新增 apps/admin；独立服务建立自己的 API、镜像与数据职责。app 之间通过接口协作，不导入对方源码。

第二个 Web app 出现后按实际复用提取，以下目录不提前占位。

packages/uiweb + adminpackages/api-clientweb + adminpackages/typescript-config两个 TS app

Next.js 的 UI 和 BFF 算同一个 app。M0 尚无 Worker 时，共用核心先留在 API；真实复用出现后再提取。

部署方案

同仓开发，按应用部署

Web、API 与 Worker 各有镜像；共享包变化触发相关应用的检查和构建。

M0 · 最小环境

先跑通一条分析链路

  • Next.js Node 应用
  • FastAPI + 进程内 Runner
  • PostgreSQL + 本地产物
  • 受控数据与隔离计算实验

进程重启后，未完成任务标记为中断，需要明确重新发起。

M2 · 可靠执行

把执行从 API 中分离

  • Next.js + API 独立进程
  • Temporal + Worker + Dispatcher
  • Sandbox Gateway + 执行器
  • S3 产物与持久数据库

用 Docker Compose 复现环境，验证重复投递、失败恢复与等待。

后期 · 云端参考

按负载与边界扩容

  • Ingress + Web / API 副本
  • 按任务类型划分 Worker 池
  • 独立隔离执行节点
  • 数据库、S3 与 Temporal 运维

容量、权限和恢复目标决定部署方式；Kubernetes 作为后期选项。

部署时重点验证SSE 全链路不缓冲会话跨副本有效迁移只执行一次API 兼容滚动升级

选型说明

几个容易混淆的决定

用了 Monorepo，就等于用了微服务吗？

仓库组织和运行架构是两个维度。API 与 Worker 共享领域包、数据库并协调发布时，仍属于模块化后端。拆为独立微服务还需要稳定契约、数据所有权和运维边界。

所有公共代码都要马上放进 packages 吗？

先记录真实消费者。单应用内可复用的代码仍留在 app；两个应用确实使用同一能力，再提取公开入口与兼容规则。跨语言共享依靠 API / Schema，Python 库不能直接成为浏览器依赖。

哪些 Turbo 任务适合缓存？

确定性的构建、静态检查和离线单测可以缓存。迁移、seed、部署、真实模型评测与外部状态测试不缓存。锁文件、工具链与构建环境变化必须使相关缓存失效。

这张宣传页也需要 Next.js 吗？

本页是独立的静态课程介绍，可直接打开或静态托管。Next.js 是 DataAgent 产品应用的技术选择，承担实际工作台和 BFF。
